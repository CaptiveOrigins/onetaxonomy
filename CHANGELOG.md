# Changelog

## Unreleased

- Linking tree tips to taxa. React: `TipLinker` is a step where a person confirms which taxon each tip of a phylogeny stands for. Each tip's name is matched exactly (letter case aside) against the dataset's taxa and synonyms with core's `findByName`; a match is proposed, never applied. Each tip is accepted, changed to another taxon (several taxa with the same name are all offered, with authorship, rank, source and id), found by another exact name, or left unlinked, and unlinked tips are listed. "Accept all exact unique matches (n)" takes, in one action, only tips with one match by accepted name or synonym; a single misapplied or provisional name waits for a check. One taxon on two tips is flagged, since comparison refuses that. Confirming makes a new phylogeny record with the links in each tip's `concepts` and a `conceptLink` note in its annotations; the record shown is never changed. Focus moves to the step's title, and each decision is announced in a status region. `proposeTipLinks` and `linkedPhylogeny` do the same without the UI. Mac app: "Link tips to taxa…" opens the step for the tree shown, and "Add tree…" brings a Newick, NEXUS or phyloXML file into the open checklist or snapshot, so a tree opened alongside its taxa can be linked and then compared. Both add to a new, unsealed snapshot; Save snapshot… suggests a `-linked` (or `-with-trees`) name and refuses every file the dataset came from.
- React explorer: a support threshold field ("Collapse support below", applied on Enter or leaving the field, with a Clear button) collapses low-support branches and says what it did in a status region: "3 branches below 70 collapsed; 2 have no support value." It's disabled for classifications, with the reason beside it. A "Compare with…" panel appears when another phylogeny is loaded or given (`compareWith`): Robinson-Foulds raw and normalized, tips in only one tree, the clades or splits that differ (each clade in the shown tree can be selected), and the reason when the trees can't be compared. With `onRooted`, "Midpoint root" and "Root on this tip/clade (outgroup)" make a new rooted record and hand it to the host; the record shown never changes. A rooted record's `rooting` note is shown under the toolbar and in About, exports and prints.
- Mac app: opens NEXUS (`.nex`, `.nexus`, `.nxs`, and `.tre`/`.tree` files that start with `#NEXUS`) and phyloXML (`.xml`, `.phyloxml`). What the reader skipped is listed in the notes with its line, and rooting that a file leaves unsaid is asked, not guessed. Rerooting or midpoint rooting adds the new tree to the open dataset as a new, unsealed snapshot and shows it; Save snapshot… suggests a `-rooted` name, and saving over the file that was opened is now refused for every save. Comparison in the Mac app refuses trees whose tips aren't mapped to taxa, which includes every Newick, NEXUS and phyloXML file it opens, since it never maps tips by label.
- Core: `comparePhylogenies(a, b)` gives the Robinson-Foulds distance (raw and normalized) between two hypotheses on the tips they share, and lists the splits or clades each has that the other lacks. Tips are matched only through explicit concept mappings; tips in only one tree are listed, not dropped. It compares unrooted unless both are explicitly rooted, and refuses unmapped or ambiguous tips and forests.
- Core: `rerootPhylogeny` (on an outgroup of one or more tips) and `midpointRoot` (only when called) make a new phylogeny record whose `rooting` says the method, the outgroup and the record it came from. The input is never changed. Support stays with its split when branches turn around. `Phylogeny.rooting` gains optional `outgroup` and `from` fields, in the JSON Schema too.
- Core: the `collapseBelowSupport` view action draws branches with support below a threshold as polytomies. The projection lists them (`supportCollapse`, `counts.supportCollapsed`) and `describeView` discloses them. The hypothesis keeps every branch, and branches with no support value are never collapsed.
- Import: NEXUS (`nexusAdapter`, `readNexus`: TREES blocks with TRANSLATE tables) and phyloXML (`phyloXmlAdapter`, `readPhyloXml`: clades, names, branch lengths, confidence, taxonomy) readers. Both carry the source's license and citation, warn about what they skip, and refuse malformed input with the line. `ImportWarning` gains a `line` field.
- Accessibility audit against WCAG 2.2 AA (`docs/test-audit.md`, 2026-11-11). React: selected and dropped labels, the "Proposed by" badge, weak-support values, errors and lesson cautions now meet 4.5:1 contrast in light and dark, and text fields have 3:1 borders. The download menu takes focus and works with arrow keys and Escape. Refusals and failed exports are announced in a status region that is always there, and a failed PNG export now says so instead of failing silently. The outline reads † as "extinct" and says it allows several selections. The drawing's keys (arrows, + and −, 0, Escape) and the outline's keys are written in the drawing's label and the inspector's hint. Lesson modes take one Tab stop and move with arrow keys, and a caution starts with "Caution:" rather than relying on color. Exported SVGs were written with `xmlns` twice in tests, which isn't valid XML; they now have it once, with the title and description first. Mac app: Light or Dark chosen in Settings now applies to the explorer as well (before, Light on a dark Mac drew near-white text on white), the window has a level-one heading, and text fields have 3:1 borders. No screen reader was used.

## Mac app 0.1.1

Fixes saving in the Mac app. 0.1.0 wasn't given permission to rename its temporary file over the chosen one, so a save very likely failed and left a `.tmp` file beside it. That was missed because the app's tests run without Tauri's permission checks. Nobody has saved with a built 0.1.0 or 0.1.1 yet: please try a save after installing.

- Mac app: opening a snapshot with no checksum now says it isn't sealed, so a sealed file whose checksum line was deleted no longer opens silently. Saving can now rename its temporary file over the chosen one (the app wasn't allowed to before, so saves failed), and a failed save removes the temporary file, or says it couldn't.

## 0.1.0-alpha.3

- Import: a Darwin Core Archive entry that is cut short, or doesn't unpack to its stated size, is now refused with an error naming the file, instead of being read in part.
- First test audit (`docs/test-audit.md`), with tests for the studio's atomic save.

## Mac app 0.1.0

- First release of OneTaxonomy for Mac.
- The Mac app can't update itself yet. Releases have no signing key, so download the new DMG instead. Signed updates can come in a later release.
- Documentation: names the OneOrigin suite.
- The repository moved to github.com/CaptiveOrigins, including the address the Mac app checks for updates.

## 0.1.0-alpha.2

- Proposed mode: drag a taxon onto a new parent (or choose one from a list) to model your own arrangement. Moves are reversible, carry the author's name, travel with the view file, and can be compared side by side with the accepted tree. The accepted data never changes.
- Core: `Proposal`, `applyToClassification`, `applyToPhylogeny`, `compareHierarchies`, and the view actions `startProposal`, `proposeMove`, `revertMove`, `endProposal`.
